# Регистрация существующей сессии ChatGPT или ZAI

Rust-ядро Herder может зарегистрировать уже открытую сессию через настроенный
AHAP-адаптер. Регистрация возвращает стабильный `session_ref`, по которому другие
авторизованные клиенты могут получить сведения о сессии и отправить ей сообщение.
Создавать новый разговор для этого не требуется.

## Настроенный экземпляр и идентификатор разговора

Сначала выберите точный `instance_ref` из `discover` с `action: "instances"`.
Экземпляр задаёт узел, провайдера, браузерный профиль и проверяемую учётную запись.
Для ChatGPT и ZAI этот маршрут берётся из защищённого owner profile и существующего
browser AHAP runner. Регистрация не принимает URL подключения к браузеру, cookie,
произвольный transport или новые права доступа.

`native_session_id` — существующий идентификатор разговора у выбранного провайдера.
Он не является Herder `session_ref`. Нельзя выбирать первый открытый разговор или
первый подключённый профиль, чтобы угадать собственную сессию. При регистрации
адаптер проверяет разговор по точному идентификатору и возвращает соответствующие
native ID и harness. Несовпадение или отсутствие проверяемой сессии не создаёт
привязку.

Один native ID в двух экземплярах имеет два разных Herder-адреса. Адрес включает
узел, экземпляр и native ID; workspace в идентичность сессии не входит.

## Зарегистрироваться и объявить workspace

Вызов инструмента `session`:

```json
{
  "action": "register",
  "instance_ref": "chatgpt-profile-a",
  "native_session_id": "existing-conversation-id",
  "workspace": {
    "node_ref": "worker-node",
    "path": "/work/agent-herder",
    "project_ref": "agent-herder",
    "purpose": "Регистрация и обмен сообщениями между сессиями"
  },
  "request_key": "register-conversation-001"
}
```

`chatgpt-profile-a` — условное имя экземпляра. Для ZAI используйте ту же форму
запроса, выбрав точный `instance_ref` его записи из `discover.instances`.

Сохраните `session_ref` из успешного результата. Используйте его в следующих
вызовах, включая вызовы после переподключения. Та же проверенная нативная сессия
в том же экземпляре сохраняет свой адрес при повторной регистрации.

`workspace` необязателен. В объявлении обязательны `node_ref` и абсолютный `path`;
`project_ref` и `purpose` необязательны. Узел workspace может отличаться от узла,
на котором открыт браузер. Это явное заявление о месте работы, а не доказательство
доступности каталога, не блокировка, не exclusive claim и не выдача файловых прав.
Отдельные `resource.claim` и `resource.release` сохраняют своё значение.

Повторите запрос с тем же `request_key` только с тем же содержимым. Изменение
содержимого при повторном использовании ключа отклоняется. Для нового действия
используйте новый ключ. Повтор старого запроса регистрации не должен отменять
более позднее объявление workspace.

## Получить сведения о своей зарегистрированной сессии

Вызов инструмента `session`:

```json
{
  "action": "context",
  "session_ref": "session:returned-by-registration"
}
```

Результат содержит адрес выбранной сессии и её объявленный workspace. Поле
`is_self` сообщает, подтверждена ли принадлежность этой сессии текущему соединению
доверенной привязкой.

Явно переданный `session_ref` означает авторизованный запрос контекста указанной
сессии. Сам по себе этот аргумент, metadata MCP-клиента или регистрация не создают
`VerifiedSelfBinding`. Поэтому обычный owner-клиент может получить корректный
контекст с `is_self: false`. Вызов `{"action":"context"}` без `session_ref`
сохраняет прежнее требование доверенной self-binding и возвращает
`self_binding_required`, когда такой привязки нет. Herder не угадывает текущую
сессию по cwd, названию или первому элементу списка.

## Обновить или убрать workspace

Вызов инструмента `session`:

```json
{
  "action": "workspace",
  "session_ref": "session:returned-by-registration",
  "workspace": {
    "node_ref": "worker-node",
    "path": "/work/agent-herder-worktree",
    "project_ref": "agent-herder",
    "purpose": "Проверка реализации"
  },
  "request_key": "workspace-update-002"
}
```

Для удаления объявления передайте `"workspace": null` с новым `request_key`.
Обновление не меняет `session_ref` или маршрут доставки. Объявление хранится
вместе с регистрацией в существующем защищённом store и доступно после рестарта.

## Найти сессию и отправить сообщение

Вызов инструмента `sessions` показывает разрешённые зарегистрированные сессии
с их адресами и workspace:

```json
{
  "action": "list",
  "instance_ref": "chatgpt-profile-a"
}
```

После выбора получателя вызовите `deliver`:

```json
{
  "action": "session",
  "session_ref": "session:recipient-reference",
  "message": "Проверь, пожалуйста, изменения в своём workspace.",
  "mode": "queue",
  "request_key": "message-to-recipient-001"
}
```

Регистрация не отменяет проверку прав на получателя. Для браузерных адаптеров
применяется существующий режим `queue`; ядро допускает его только для наблюдаемой
idle-сессии. `current` или `start` не становятся доступными из-за регистрации.
Действующий HumanStop также сохраняется при повторной регистрации.

Доставка использует прежние durable intents и MCP Tasks. При подключении напрямую
к native MCP сохраните возвращённый `taskId` и проверяйте его через `tasks/get`.
Через совместимый endpoint `herder-compat` возвращается `task_ref`; для проверки
вызовите инструмент `compat_task`:

```json
{
  "action": "get",
  "task_ref": "returned-task-reference"
}
```

Принятие запроса не равно доказанной доставке. Повтор того же запроса с тем же
ключом использует сохранённый результат и не должен отправлять сообщение второй
раз. При неизвестном исходе проверяйте исходную квитанцию, прежде чем предпринимать
новое действие.

## Проверки

Из корня репозитория:

```sh
cargo test --locked --manifest-path crates/herder/Cargo.toml --test browser_registration
```

Этот набор запускает настоящий Rust stdio entrypoint с отдельным fake AHAP
процессом и временным защищённым хранилищем. Он проверяет оба провайдера,
разделение профилей, устойчивость регистрации и workspace после перезапуска,
проверку нативной идентичности, адресную доставку с дедупликацией и сохранение
HumanStop. Он не открывает браузер и не отправляет сообщений в настоящие чаты.
Отдельная проверка подключённого браузерного маршрута нужна, чтобы подтвердить
его доступность и работоспособность для конкретного профиля.
