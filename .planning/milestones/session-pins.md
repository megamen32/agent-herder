# Следующий майлстоун: закрепления и компактные сведения о сессиях

Статус: в работе. Пользователь 13.10.2026 явно поручил выполнить сохранённый майлстоун и проверить на сайте.

## Результат для пользователя

- Закрепить или открепить любую доступную сессию в левом списке.
- Закреплённые сессии находятся сверху и сохраняют закрепление после перезагрузки.
- Под названием — одна небольшая приглушённая строка, например `Codex · 100`
  или `ZCode · M1`; без дополнительных широких карточек.
- На десктопе при наведении и клавиатурном фокусе показывается компактная
  подсказка: полное название, среда, машина, путь проекта (CWD), модель,
  состояние и последнее обновление, если эти данные подтверждены.

## Критерии приёмки

- [ ] PIN-01: личное закрепление не запускает, не останавливает и не продолжает
  сессию; отличается от автоматического runtime pinActiveSessions.
- [ ] PIN-02: ключ закрепления учитывает машину, среду и нативный ID; одинаковые
  ID разных узлов не смешиваются. В поиске/фильтрах нет двойных строк.
- [ ] META-01: компактная строка среды и машины читается на десктопе и мобильном
  экране; длинное название не вытесняет её и не увеличивает блок до большой карточки.
- [ ] META-02: подсказка не перекрывает действие закрепления и не обрезается
  боковой панелью. Наведение и клавиатурный фокус дают одинаковые сведения.
- [ ] META-03: текущий подтверждённый CWD отличается от каталога запуска.
  Неизвестные сервер, модель или путь честно обозначаются; сведения не выдумываются.
- [ ] META-04: реальный сайт проверен на десктопе и мобильном экране через
  managed browser на44/88; нативные сообщения не отправляются для проверки.

## Границы

Текущая задача исправляет отображение доставки. Этот майлстоун только записан;
его выполнение не включено в текущую поставку. Без нового планировщика,
реестра машин или изменений выбранных моделей и авторизации.

## Следующий шаг после этого майлстоуна

По новому пожеланию пользователя: единые закрепления Herder и нативных Codex/ZCode (и других поддерживающих закрепления сред), с синхронизацией в обе стороны. Пока только запланировано; требуется проверить официальные native pin API и конфликты. Личные браузерные закрепления текущей поставки не выдаются за native pins.
