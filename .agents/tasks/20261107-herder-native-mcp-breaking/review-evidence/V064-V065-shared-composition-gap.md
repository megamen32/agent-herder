## Remaining glue

The OpenCode candidate exposes the right ports: `OpenCodeCreateControl` implements `NativeCreateControl`; `OpenCodeSessionControl` implements `NativeSessionControl`. The shared `application::target::create_once` and `target::deliver` can consume these contracts. `OpenCodeReader` currently has no visible `NativeSessionReader` implementation in the candidate source. The queued V064A/V065A leaves correctly remain distinct from V064PORT/V064LIVE/V065PORT/V065LIVE.

Smallest composition slice to unblock the application path: first provide/verify an OpenCode reader projection implementing `NativeSessionReader` for the exact bound instance/session; then add one source/fake composition test using the shared target APIs, a temporary v2 Writer, an authorized identity/grant, an exact `OpenCodeCreateControl` fake response and a deterministic server SessionRef issuer. Assert a single create, store reopen resolves the same native ID/instance, the follow-up shared delivery reads that exact target and submits exactly once in Queue mode, and the durable receipt resolves/reopens without a second native effect. Keep unsupported Current/Start and UNKNOWN non-retry behavior as established by existing port tests. Do not repeat V064LIVE or V065LIVE.

A general “create complete only after native session readback” guarantee still needs an explicit composition assertion; V064LIVE already proves provider readback separately, but the current generic create API commits from the matching create receipt before such a native read. Do not mark V023/V064A/V065A complete or remove their dependencies from these receipts alone. No installed/public MCP consumer proof is present here.
