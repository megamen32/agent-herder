## Как читать разбиение

Исходный Vnnn теперь последний шаг цепочки VnnnA → VnnnB → Vnnn. Он сохраняет полную исходную приёмку; incoming зависимости ждут этот итог. Все новые шаги <=15 минут. Один исполнитель может пройти готовую цепочку без повторного разрешения. Не назначать новый worktree/review/deploy на каждую строку. Проверка/commit объединяет цельный результат, а не бумажное разбиение.

E-листья — поставки на изолированный стенд и ранние native сценарии. S-листья — группировка этапов, не дополнительный scheduler барьер. R-листья — общие ресурсы. D-листья — работа Astra над данной ревизией, не задачи реализации продукта.

Ресурсный контракт RESOURCES.md заменяет project-only layout. `resource` заменяет `workspace`; число инструментов 14. Notes/worktrees сохраняются через declare, list/get. Global phone не записывается как фиктивный project. Один owner store, один offline/MCP writer. LHC хранит собственный план. Существующий s21-lease переключается на общую authority без двух владельцев; тестовых звонков/уведомлений людям нет.

## Оценки и неизвестности

ESTIMATES.md содержит расчёт оставшейся работы из фактического DAG, без фиктивной даты. Неизвестные API, аккаунты, внешние paths и исправления не укладываются обещанием «15 минут»; входной research gate сначала делает их конкретными. Плановый fallback модели не доказывает назначение исполнителя. Каждый новый дефект получает собственный bounded шаг до запуска.
