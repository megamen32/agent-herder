# Усилия, критический путь и календарь — ревизия 5

## Основание и допущения

219 bounded slices: **104,5–201,3 инженерного часа**. Это условный объём известной программы, не fixed-price оценка полного неизвестного rewrite. Minimum/maximum каждого листа включает его адресную проверку; повтор на финальном candidate отдельно показан там, где нужен. Ни один leaf больше 60 минут. Отсутствующее native API или необходимость fork клиента не влезают в фиктивный час: соответствующий gate выдаёт доказательство/блокер, затем граф пересчитывается до реализации.

Условия: исполнители знакомы с Rust/async и продуктом; штатные SDK/CLI доступны; один подтверждённый transport на продукт, а не реконструкция закрытого API; авторизованные test profiles и native runners готовы; внешние consumer write paths разрешены. Модель исполнителей и токены здесь не оценивались.

## Критический путь

Зависимостный нижний предел при неограниченном числе исполнителей: **20,3–37,8 часа**. Это не ETA команды: core/adapter lanes и доступные slots ограничивают параллелизм. Основная цепь: SDK/config/identity → application/Tasks → первая native вертикаль → потребительский контур/миграция → review → legacy removal → final candidate → контроль adapters → preflight/cutover → Linux/macOS → две независимые приёмки → handoff. Полная машинная цепь находится в [forecast.json](review-evidence/forecast.json).

Вычисление: DAG longest path по диапазонам; для календаря — list scheduling с приоритетом оставшегося критического пути, максимум N исполнителей и одним активным листом на lane. Это воспроизводимая допустимая раскладка, не доказанный оптимум. Зависимости берутся из тех же входов, что граф LHC. Глобальная сумма не делится механически на N.

**Плановый календарь с резервом для четырёх исполнителей: 9–17 рабочих дней**, при 6 продуктивных часах на человека в день. Это сценарий планирования, не обещанная дата: учитывает примерно 16–32 часа дополнительной последовательной работы на критическом пути (интеграционные исправления, повтор проблемных lanes и операционные окна). Дата старта не назначена. Ожидание чужого доступа/релиза SDK/доступности аккаунта добавляется отдельно и не ограничено этой вилкой.

Для двух исполнителей ориентир с тем же последовательным резервом: 12–24 рабочих дня; для одного — 24–46 рабочих дней с трудовым резервом ниже. Внутри четвёрки один интегратор отвечает за core contracts, остальные — адаптеры/consumers/QA; роли переходят между независимыми slices после завершения входов. Нельзя занимать четыре slots четырьмя одновременными правками одного adapter. Native общий профиль также нельзя параллельно делить.

## Неопределённость и резерв

Не добавляем пустые часовые задачи «починить всё». Отдельный **плановый резерв усилий 35–70 часов**, вне суммы 219 листьев: это allowance, не уже определённые работы и не верхняя гарантия. При материализации риска создаются конкретные leaves <=60 минут с фактом/приёмкой, пересчитываются зависимости и ETA. Полный бюджетный ориентир при указанных допущениях — **139,5–271,3 инженерного часа**.

## Что не входит в эти цифры

Общее обследование старой архитектуры или флота, Windows, универсальный plugin system, автопоиск инфраструктуры, HA authority и поддержка любого неизвестного browser provider исключены. Конкретный Browser Chat endpoint исходного scope остаётся обязательным и определяется его gate. Исторические отклонённые R/L/M листья не входят в сумму. Затраты этого независимого ревью не приписаны будущей реализации.

При наступлении отрицательного gate baseline перестаёт быть прогнозом: сначала обновить план, не продолжать показывать прежние числа как confirmed ETA.
