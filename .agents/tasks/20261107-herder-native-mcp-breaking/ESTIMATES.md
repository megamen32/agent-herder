# Оценки Agent Herder v1 — нулевая ревизия

**76,5–145,8 инженерного часа** для 159 bounded slices. Это условная сумма при подтверждённых native/client контрактах, не гарантия трудоёмкости отсутствующего API. Каждый лист <=60 минут; отрицательный gate требует нового конкретного разбиения, а не продолжения работы под фиктивной оценкой.

## Календарь

Критический путь зависимостей при неограниченных ресурсах: **20,3–37,8 часа**. Он почти не сократился после исключения шести адаптеров: остаются общий core, миграция и последовательная приёмка. Сокращение scope уменьшило общее усилие на **28–55,5 часа** и освободило слоты.

Расписание вычислено по DAG, N исполнителям и одному активному листу на lane (adapter/consumer/module). Приоритет — оставшийся критический путь; это проверенная допустимая, не доказанно оптимальная раскладка. Сумма не делится механически на N. Данные: review-evidence/forecast.json и schedule-*.json.

| Исполнителей | Рабочие часы календарного пути | При 6 продуктивных ч/день, без резерва |
|---:|---:|---:|
| 1 | 76.5–145.8 | 13–25 рабочих дней |
| 2 | 41.9–79.2 | 7–14 рабочих дней |
| 4 | 27.9–52.8 | 5–9 рабочих дней |

Для четырёх исполнителей рабочий ориентир с резервом — **7–13 рабочих дней**: к 27,9–52,8 часа добавлены 12–24 часа последовательной интеграции/исправлений/операционных окон, по 6 продуктивных часов в день. Дата старта ещё не назначена. Долгое ожидание внешнего API/доступа/аккаунта в эту вилку не входит и может её превысить.

Плановый резерв усилий **25–50 инженерных часов**, отдельно от 159 листьев. Общий бюджетный ориентир при выполнении допущений — **101,5–195,8 часа**. Резерв не является задачей «починить всё»: каждый обнаруженный дефект получает конкретный лист RED/fix/GREEN <=60 минут и пересчёт календаря. Для двух исполнителей с последовательным резервом — около 9–18 рабочих дней; для одного с трудовым резервом — 17–33 рабочих дня.

## Допущения и важные неизвестности

- Исполнители знакомы с Rust/async, тестовые профили и native runners доступны; common contracts ведёт один интегратор. Нет параллельной записи в один adapter или использования одного browser profile.
- Основной MCP client/gateway действительно поддерживает revision/extensions: V003. При отрицательном результате исправить конкретный consumer/SDK gap до массовой реализации; никаких скрытых jobs/downgrade.
- Для пяти продуктов существует один доступный versioned native route. Каждый adapter начинается с узкого gate. Отсутствующий route/hook — неизвестный объём, явно записанный в connection leaf.
- Release target имеет одну обязательную точку выполнения. Если два runner меняют один объект, нужен отдельный target-specific дизайн; текущая оценка его не скрывает.
- Write paths и полномочия Hub/LHC/Notice Place/UserIO/Board/секретаря подтверждаются узким target gate. Изменения других проектов эта планирующая сессия не выполняла.
- Maintenance cutover выполняется при остановленных writers, сохраняет UNKNOWN/holds/receipts. Отложенные среды отключаются явно, их native histories не удаляются.
- Windows, HA authority, universal plugin framework и шесть adapters из NEXT-UPDATE не входят в v1.

Граф очищен от исторических листьев, поэтому прежнее завышение усилия за счёт deferred устранено в источнике. Автоforecast LHC всё равно не является назначенной датой запуска и не заменяет эту lane/6ч-день модель. Отсутствие подтверждённого native API явно делает полный ETA условным.
