# Единые ресурсы Agent Herder v1

Решение владельца 07.11.2026: деплой, телефоны, рабочие деревья и планы должны использовать общий механизм ресурсов. Это контракт для реализации, не утверждение о работающей функции.

## Минимальная модель

Ресурс имеет неизменный `resource_ref`. Отдельные поля описывают:

- `scope`: `global`, `project(project_ref)` или `node(node_ref)` — принадлежность и обнаружение; область не выдаёт права.
- `kind`: `workspace`, `deployment`, `device`, `plan` или описательный иной вид. Новое устройство не требует нового MCP-инструмента. Не вводить язык исполнения произвольных команд в metadata.
- `external_ref`: устойчивая идентичность внешнего объекта. Для телефона она не зависит от USB-пути; для плана — от имени текущего исполнителя. Дубликаты подтверждённой внешней identity не создают независимых блокировок одного объекта.
- `authority_ref`: единственное каноническое хранилище descriptor и owner. Это не нода подключения устройства.
- `attachment`: текущий node/route reference, наблюдаемая доступность и `observed_at`. Отключение не удаляет descriptor и не освобождает owner. Маршруты с секретами в карточку не попадают.
- `revision`: CAS для изменения descriptor. Изменение подключения не меняет resource_ref и claim.
- `owner`: проверенный principal, сессия при доказанной привязке, claim_id, цель и временные сведения из единственного owner.json. Это состояние владения, а не копия в SQLite.

Доступность (`available/unavailable/unknown`) и занятость (`free/owned/unknown`) независимы. Занятый отключённый телефон — допустимое состояние. Таймаут authority не означает свободный ресурс.

## Один инструмент `resource`

Он заменяет `workspace` в каталоге; итог остаётся 14 инструментов. Остальные инструменты перечислены в RUST-DESIGN.md.

| Действие | Результат |
|---|---|
| `list` / `get` | Найти разрешённые ресурсы по scope/kind, прочитать descriptor, владельца, freshness и разрешённый способ связи. |
| `register` / `update` | Зарегистрировать ресурс или изменить descriptor по CAS с проверкой прав. |
| `claim` / `renew` / `release` | Атомарно получить, продлить или освободить исключительное владение через общий storage. |
| `declare` | Записать или убрать собственное рабочее намерение/заметку, связанные с ресурсом; это не владение. |

Каждое действие — отдельная schema-ветвь с discriminator и запрещёнными лишними полями. `declare` сохраняет обязательные coordination notes: worktree, scope работ, purpose, срок заметки, собственное изменение/удаление. Для списка/чтения используется общий list/get; отдельного note-store API не добавлять. Read-only наблюдение за ресурсом не требует exclusive claim, но требует прав чтения.

MCP Resources публикуют карточки и изменения для чтения/подписок. Протокольный ресурс не обеспечивает исключительное владение сам по себе; claim выполняется инструментом и той же offline библиотекой.

Пример отказа: «Телефон S21 занят сессией “Проверка Android” для проверки авторизации. Владение не получено, действий с телефоном не было. Свяжитесь с владельцем по разрешённому адресу либо выберите свободное устройство». При неизвестном исходе claim предложить чтение прежнего nonce, не автоматическое новое занятие.

## Один источник данных и offline доступ

```text
<root>/storage.json
<root>/resources/<resource_id>/resource.json
<root>/resources/<resource_id>/owner.json
<root>/resources/<resource_id>/guard.lock
<root>/projects/<project_id>/project.json
<root>/projects/<project_id>/snapshots/context.json
<root>/RECOVERY.md
```

Resource descriptor содержит markers storage/resource/schema и scope. При необходимости project descriptor проверяется дополнительно. Нельзя помещать глобальный телефон в фиктивный проект ради существующего layout. Индексы по project/node — производные, не второй источник владения. Один ресурс не копируется по каталогам каждого проекта.

MCP и offline `herder resource list|get|register|update|claim|renew|release` используют одну библиотеку и authority. После проверки markers отсутствие owner.json означает возможность атомарного claim без вопроса человеку. Все гарантии guard/rename/fsync/UNKNOWN из RECOVERY-STORAGE сохраняются. Каталог и descriptor отсутствуют — ресурс не зарегистрирован, а не свободен. Автоматического failover authority нет.

## Кто действительно исполняет действия

Herder хранит reference и координацию. LHC остаётся владельцем содержимого/истории плана. Телефоном управляет существующий device runner; деплоем — release entrypoint. Herder не получает собственный редактор планов, ADB framework или workflow engine.

Вход, выполняющий конфликтующее действие, проверяет текущий claim. Для deploy/device используются одна точка выполнения и execution lock; смена владельца не означает отмену уже принятой операции. Неизвестный внешний исход сначала сверяется. Для LHC запись проверяет claim и revision самого плана. Совместить старый s21-lease с общей authority нужно переключением одного writer; две независимые истины «телефон свободен» недопустимы.

Resource claim не выдаёт права на запрещённые операции. Тестовые звонки людям и тестовые уведомления владельцу запрещены. Проверка устройства использует разрешённое чтение тестового состояния. До выдачи второго физического телефона его независимость проверяется fixture descriptor; реальное подключение записывается после предоставления устройства, без придуманного serial/route.

## Парето и приёмка

Первая версия: descriptor, list/get, права, CAS, один exclusive claim, offline доступ, один реальный потребитель каждой нужной категории. Не нужны очереди ожидания, приоритеты, вложенные блокировки, shared/exclusive upgrade, автообнаружение всего оборудования, distributed consensus или собственный scheduler ресурсов.

Проверяемые сценарии:

1. Два телефона имеют разные resource_ref. Смена подключения S21 сохраняет его identity и владельца; второй ресурс свободен независимо.
2. MCP и offline CLI одновременно занимают один ресурс: один победитель. Чужой release отказан.
3. Недоступный телефон виден в реестре; неизвестное состояние authority не выдаётся за free.
4. Обычный device entrypoint отвергает старый claim. Проверка не звонит человеку.
5. LHC хранит план у себя; два писателя одного plan ref получают конфликт, а разрешённое чтение продолжает работать.
6. Recovery без MCP обнаруживает global/project/node ресурс по заранее установленной инструкции.

Карта реализации: R001–R004, V036–V043, V044–V045; внешние входы R005A/R005B/R005 и R006A/R006B/R006; инструкции V125/V126; финальная приёмка V142/V159. Каждый исполнимый шаг <=15 минут, неизвестные внешние входы имеют отдельный research gate.
