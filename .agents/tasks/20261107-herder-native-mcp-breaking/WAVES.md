# Волны и исполнители: четыре у Теры плюс самостоятельные сессии

Решение владельца: максимально быстро закончить, не перегружая одного руководителя. Общую оркестрацию ведёт Astra; Terra управляет максимум четырьмя core исполнителями. Шесть самостоятельных сессий из ORCHESTRATION.md работают напрямую по своим цепочкам. Общий исходный пул — до10 исполнителей, руководство и надзор отдельно.

Волна — наблюдаемая группа готовых назначений, не общий барьер. Следующий шаг запускается сразу после своих depends_on. Количество исполнителей меняется автоматически по готовности и конфликтам; свободная сессия получает от Astra следующий независимый участок, а не ждёт завершения всей группы.

| Практическая волна | Исполнителей | Результат/условие перехода |
|---|---:|---|
| Контракты и соединения сейчас | до10: core<=4 +6 самостоятельных | Core/Task schema, translator handshake, resources manifest, native profile/connection gates. Доступ проверяется на конкретной линии. |
| Первое настоящее общение | столько же, при готовых входах | T011 и локальные create/deliver/read → E001/E002. Свободный исполнитель продолжает готовый свой шаг. |

| Consumers, импорт и платформы | переменно до10 | После закрытия adapter участка Astra передаёт освобождённой сессии конкретный consumer/OS lane, сохраняя предел4 у Теры. |

| Cutover и передача | 1 writer на target; независимые проверки параллельно | Сериализуется только реальная запись общей цели. После неё Linux/macOS/communication/recovery идут по готовности. |

## Расчёт по конкретным шагам

Для текущего снимка с translator и фиксированными границами шести сессий расчёт даёт 15.33–23.0 часа полезной работы по расписанию. Это не ETA: SDK/auth/runner ожидания и неизвестные исправления отсутствуют в расчёте. Прежние 13–19 часов относились к старому графу без translator и к свободному назначению любого исполнителя на любой участок; их нельзя обещать после изменения scope/организации.
