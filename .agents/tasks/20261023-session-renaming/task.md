## Исходный запрос пользователя

Добавить в Agent Herder настоящее переименование уже существующих сессий, обязательно Codex.
Пользователь не понимает старые заголовки. По точному `host + harness + sessionId` меняется
native title существующего диалога: не создаётся новый диалог, не запускается модель,
не прерывается активный ход. Поддерживаемый нативный API, без правки баз/индексов Codex.
`session_identity` переименованием не является.

Разделение ТРЁХ ПОЛЕЙ одобрено владельцем: постоянный проект, текущая бизнес-цель,
текущий этап плана. Хранятся в существующих метаданных Herder, короткий title собирается
в формате «Проект | цель | этап». Содержательные поля не обрезаются произвольным маленьким
лимитом. Переименование — ручное или однократное при реальной смене задачи; никаких
периодических LLM-запусков и тяжёлых хуков ради заголовков.

Граница уточнена владельцем: «бизнес-цель» — описательные метаданные для пользователя.
`thread/goal/set` не вызывается, native execution goal чужих сессий ради заголовков
не меняется. Codex-сессии не будить и не запускать ради проверки названий.

Довести до доступной операции MCP через GPT Admin и штатной публикации/установки Herder.
Чужие активные сессии рестартом не ломать. Проверить: кириллица/Unicode, неверный ID,
пустое имя, сохранение thread ID и истории, сохранение активного хода, повторное чтение
нового title нативным readback и через Herder. Переименование не должно потреблять
модельную квоту; защита запуска/продолжения моделей остаётся прежней. При отсутствии
возможностей — явный unsupported, не ложный успех.

## Ограничения приёмки

- Нативный readback нового title через `thread/read` и через Herder (`agent_info`).
- Thread ID, история и активный ход той же сессии не меняются.
- Переименование не вызывает модель и не потребляет квоту.
- Неверный ID, пустое имя, кириллица — явный результат, не ложный успех.
- Harness без нативного API — явный `unsupported`.
