# Fast/Normal существующей Codex-сессии

Прямое поручение: Herder должен менять скорость уже существующей сессии,
сохраняя выбранную модель, effort, историю и текущую работу.

Выбран минимальный путь: штатный `thread/settings/update` с точным `threadId`
и единственным изменяемым полем `serviceTier`. Fast соответствует `fast`,
Normal соответствует `default`. Изменение действует на последующие запросы;
текущая генерация не прерывается. Нельзя подменять это новым сообщением,
новой сессией, холодным resume или записью глобального config.toml.

Живая приёмка выявила: пустой RPC ack подтверждает только приём, а уведомление
получают подписанные клиенты. Проверенный штатный seam для уже loaded thread:
`thread/resume({threadId,excludeTurns:true})` без overrides возвращает snapshot
текущих model/effort/tier и атомарно подписывает клиента, не создавая turn.
Этот attach допускается только после exact loaded/list и thread/read проверки;
для незагруженной сессии остаётся отказ. Это исправляет чтение исхода без
повторения двух UNKNOWN попыток Fast (одна tester, одна Root).

Исполнители: codex_live_tier — адаптер и типы; codex_tier_controls — API/MCP/UI;
Root — интеграция, единственная установка, реальная приёмка.

QA scope: текущая собственная Codex-сессия
`01a1754f-0228-7553-bea6-cc89e40b5187`, модель до изменения `gpt-6.1-sol`.
Разрешено только переключение tier и чтение результата. Новые turn/сообщения,
перезапуск Codex, изменение global default или чужой сессии не допускаются.
Подтверждение: точная сессия и прежняя модель, native effective tier Fast,
затем Normal; при отсутствии нативного подтверждения не объявлять переключение.

Исходная установленная версия Herder `a7bd62049135c6d23f490c936edf275cef7218d9`,
PID3561979; публичный frontend пока c42d55d. Установка должна сохранить текущие
env, auth, incident/session policy, живые native сессии и чужой WIP.
