# Восстановлены понятные названия OpenCode / OpenChamber

Прямое поручение владельца 28.10.2026: вернуть ранее работавшие понятные
названия и применять их к инцидентам, вместо `project-launch-<hash>`.
Ответственный: Codex `01a17ea3-5600-7580-aba9-1badd2187dd5`, server-100.

## Причина и исправление

- Project launch использовал один name одновременно как стабильный ключ
  операции и как native title. OpenCode честно показывал техническое имя.
- Прежний rename был реализован для Codex. У OpenCode не было renameSession,
  поэтому сохранённые в Herder labels не обеспечивали нативного названия.
- `displayTitle` теперь отделён от логического name. Новая сессия получает
  title из исходного incident telemetry; durable binding хранит прежний ключ
  и настоящий native title. Повторное обращение после рестарта переиспользует
  тот же ID. Изменение title не является разрешением на новый launch.
- OpenCode rename использует документированный установленным OpenAPI
  `PATCH /api/session/{sessionID}` и последующий native GET/readback.
  Ответ 204 обрабатывается без попытки чтения отсутствующего JSON.
- Нативное переименование обновляет title в durable name→ID binding;
  история, operation_id, модель и работающий ход не заменяются.

Мои source commits в origin/main: `9c3bb7e` и `a3c8a80`.
Установленный конечный release: `9e6fc438cd6da3bf021b3b76d93f75c0b9c17c58`,
содержит оба исправления и опубликованные изменения соседнего исполнителя.
Независимый readback: systemd ExecStart указывает на этот release,
MainPID=1215739, старт 28.10.2026 13:57:11 МСК, ActiveState=active;
deployment manifest source_dirty=false, точный source_sha совпадает.

Первый промежуточный release 9c3bb7e не стартовал из-за пропущенного дерева
зависимостей в моём ручном вызове штатных build-helper функций. Зависимости
добавлены штатным release_packages_tree, сервис восстановлен. Во второй сборке
выявлен отсутствующий import join в опубликованном соседнем 9d6947b; автор
исправил его в 9e6fc43 и установил общий main. Его WIP я не редактировал.
Нативный процесс OpenCode и пользовательские сессии при этом не перезапускались.
