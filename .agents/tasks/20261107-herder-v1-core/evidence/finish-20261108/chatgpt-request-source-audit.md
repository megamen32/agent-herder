## Вывод

AHAP-конструктор напрямую создаёт driver и `BrowserChatAdapter(..., scopedIds=true, foregroundOnly=true)` (`src/ahap-browser-runner.ts:323-327`). Он не вызывает factory `createBrowserChatDriver`, поэтому фабричный 5-секундный prompt poller не включается автоматически в AHAP (`src/adapters/chatgpt-mac-cdp-driver.ts:1551-1564`). В foreground отключены prewarm и асинхронная revalidation inventory, но каждый вызов истории обходит `BrowserChatHistoryCache`: `browser-chat.ts:235-236,270-275,381-389`. Значит частое чтение вызывающей стороны превращается в повторные site HTTP, а не в чтение 15-секундно ограниченного кеша. `getSession` при флаге working тоже запускает `refreshTurnState` → `getMessages`; ChatGPT driver игнорирует переданный foreground option (`browser-chat.ts:351-365`, `chatgpt-mac-cdp-driver.ts:913-919`).

## 429 и пробелы границ

- History/list page scripts делят `globalThis.__herderChatGptReadCooldownUntil` **на уровне вкладки**, сначала проверяя timestamp (`browser-chat-api-scripts.ts:49,60-65,182-195`). При 429 Retry-After integer ограничивается 300 с; при отсутствии — 60 с. Нет общего межвкладочного запрета в этих скриптах. `getMessages` пробует следующую проверенную вкладку только после `read_cooldown`, а не после `history_http_429` (`driver:1007-1016`).
- `feedBackoff` записывает 429 list/history в Bayesian estimator (`driver:611-630`), floor 120 с, cap 32 мин, учитывает Retry-After (`chatgpt-bayes-backoff.ts:30-39,127-134`). Активный list явно проверяет Bayesian list cooldown (`driver:649-652`); прямой foreground history `getMessages` **не проверяет Bayesian history cooldown** перед вызовом — он полагается на page-local timestamp. Не считать наличие estimator глобальным ограничителем foreground history.
- Full conversation export имеет отдельный более долгий 429 backoff: минимум 300 с × 2^(strikes−1), до 10 strikes, с учётом server Retry-After; распространяет timestamp на текущую страницу (`chatgpt-full-conversation.ts:7-18`). Scope auth script намеренно выполняется независимо от history cooldown. `readablePages` и вызов `page()` имеют собственную логику выбора/создания вкладок (`driver:400-425,475-496`); закрытие вкладок само по себе не доказывает нулевой запрос, если кто-то затем вызывает этот путь. Никаких действий по созданию/закрытию вкладок этим аудитом не производилось.
