Срез 08.11.2026 после сообщения владельца о переключении GPTAdmin. Read-only: source, установленные файлы, unit metadata; HTTP/browser/native mutations не выполнялись. Изменён только этот отчёт. Результаты ниже — доказанные зависимости и прогноз отказа при отключении, **не результаты искусственного отключения**.

**Решение для интегратора:** GPTAdmin MCP уже переведён родителем на Rust stdio, `mcp_tools` + `discover` PASS по сообщению владельца. Это снимает его прежний HTTP transport dependency, но не зависимости NoticePlace, установленных hooks, UserIO worker и HTTP UI. Для выключения старого daemon требуется перенести перечисленные application contracts на V1 execution port либо явно отключить соответствующие функции. Простая замена URL/имени инструмента их не сохраняет.

## Минимальный объём, чтобы old daemon действительно выключить

1. **MCP-only consumers:** существующий launcher уже достаточен для поддержанных V1 операций; применить существующие config/plugin/GPTAdmin delivery механизмы по exact registration. GPTAdmin parent PASS уже есть. Для UserIO worker нужен небольшой adapter его трёх legacy методов и сохранённый named binding; не переписывать workspace/send loop.
2. **HTTP application consumers:** переиспользовать dependency-injected `createWebServer`/handlers и существующие stores, выделив только перечисленные необходимые routes. Подключить существующую native action boundary к Rust V1 через один reusable client; не запускать `dist/index.js` внутри bridge и не держать второй legacy native poller. Это предлагаемая минимальная реализация, **готового подключённого façade→V1 в текущем source не доказано**. Политику launch/autopilot, pending human completions, owner controls и coordination нельзя свести к «проксировать любой JSON в create». Не нужен новый daemon manager/scheduler/adapter family.
3. **До удаления oldservice:** адресно проверить policy read + incident same-session reuse без duplicate mutation, human completion replay single-winner, owner stop/disarm revision/node readback, hook inbox/activity, UserIO same-session status/messages и installed profile для policy-selected executor. Это критерии последующей интеграции; аудитор их не выполнял и PASS не заявляет. UNKNOWN admissions сохраняются.
