Исполнитель: отдельная сессия на MiniMax (OpenCode), отдельная ветка

Проект: `megamen32/agent-herder`.

## Исходный запрос владельца

1. Выключить ВСЕ опциональные хуки Agent Herder и сделать их выключенными по умолчанию:
   новые сессии, установки, обновления, fleet common-settings.
2. Не путать отключение `prohibitionsEnabled` с отключением всего hooks runtime.
3. Состояние OFF должно быть постоянным и не перезаписываться автоустановкой/синхронизацией.
4. Новые опциональные хуки — только opt-in.
5. Не отключать базовую авторизацию MCP, права инструментов, ручной Stop и защиту квот.
6. Сделать отдельную заметную вкладку «Настройки» с общим переключателем хуков и отдельными
   переключателями: понятное описание, фактическое effective-состояние, область действия,
   синхронизация.
7. Не создавать новый контроллер и не запускать бесконечный тестовый цикл.
8. Не потерять готовую ветку переименования.

| **Дефолт в коде (эта работа)** | Новый переключатель `hooksEnabled` — весь необязательный hooks runtime; дефолт `false`; `prohibitionsEnabled` тоже `false`; документ старого runtime читается как OFF | `src/hooks/state.ts`, `src/hooks/service.ts` |
| **Фактическая активация (эта работа)** | Herder не отдаёт контекст хукам при `hooksEnabled:false` → уже загруженный обработчик в живом OpenCode замолкает сразу, без перезапуска и без потери сессий | `src/web/server.ts` (`/api/coordination/context`, `/api/coordination/activity`) |

Штатный способ выключения (после публикации):

```sh
# весь необязательный hooks runtime herder на этой машине
curl -s -X POST http://127.0.0.1:18787/api/hooks/prohibitions \
  -H 'content-type: application/json' \
  -d '{"source":"owner","actor":"owner","hooksEnabled":false,"reason":"хуки мешают"}'

# только один хук
... -d '{"source":"owner","actor":"owner","inactiveHooks":["Stop"]}'
```

Файл состояния (он и есть источник истины):
`~/.local/state/agent-herder/autopilot-live/hooks-prohibitions.json`
ключи: `hooksEnabled` (весь runtime), `prohibitionsEnabled` (могут ли хуки запрещать),
`inactiveHooks` (хуки, выключенные поимённо), `disabledHooks` (хуки без запретов).

Общие настройки флота этот переключатель **не переносят и не включают**: он остаётся
решением узла. Поэтому синхронизация не может включить хуки обратно.
