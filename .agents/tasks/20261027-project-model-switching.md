# Автопереключение моделей при исчерпании квоты

Владелец: Codex `01a1754f-0228-7553-bea6-cc89e40b5187`.
Прямой запрос 27.10: OpenCode должен продолжать ту же работу следующей
разрешённой моделью, в том числе GLM → MiniMax. Видимый переключатель в
автопродолжении; приоритет моделей в существующих настройках проекта.

## Результат до / после

Сейчас live OpenCode fallbackForQuota=false, общий fallbackModels содержит
только omniroute/minimax-combo-m3.1. Механизм quota-recovery уже существует,
но читает список только по среде, без проектного порядка и ограничений.
После: включённое автопереключение выбирает следующую разрешённую модель
проекта по явному порядку, не меняет native session ID и не повторяет
принятые/неизвестные отправки. HumanStop и вопрос человеку блокируют запуск.

## Режим и решение

Fullcycle: изменение границы конфигурации, runtime и пользовательской формы.
Начальная оценка: 35–50 минут, активное время учитывать отдельно от ожиданий.
Рабочий путь: существующий quota-recovery + глобальный fallbackModels.
Идеал: единый выбор модели для любого запуска/восстановления, без второго
реестра и копирования credential/provider-конфигурации.
Минимальный полезный срез: одно поле fallbackModels в projectRoutes (такое же
название и формат, как у существующего общего порядка),
разрешённые/запрещённые модели остаются источником доступа; существующий
fallbackForQuota остаётся переключателем. При отсутствии проектного порядка
совместимое наследование общего порядка, отфильтрованного политикой проекта.
Независимая консультация проверяет это решение до реализации backend.

## План и границы

1. Проследить текущий механизм, получить независимую консультацию (read-only).
2. Worker: проектный выбор кандидатов, валидация/сохранение fallbackModels,
   привязка к реальному cwd сессии и существующим safety gates.
3. Lead: существующая форма проекта — приоритеты разрешённых моделей;
   понятный переключатель «Автопереключение моделей» в автопродолжении.
4. Один обзор совместного изменения; сборка canonical main, owned release.
5. Приёмка через настоящий интерфейс с собственным QA project и точной
   тестовой сессией/адаптером: сохранение порядка, выключение/включение,
   отбор следующей разрешённой модели и no-replay после принятого результата.
   Не вызывать специально quota exhaustion у реального провайдера.

## Ограничения

Не менять NoticePlace combo/контракт и ранее принятые QA receipts. Не опрашивать
MiniMax Token Plan до уже назначенного 28.10 12:00 МСК. Не создавать рабочие
копии/worktree/ветки, не менять исходники OpenCode, не трогать чужой WIP.
Не добавлять и не запускать новые тестовые кампании без поручения; текущая
задача включает реальную приёмку изменения, использовать узкий сценарий.
Тестовые уведомления/звонки людям запрещены. Чужие сессии не переключать.
