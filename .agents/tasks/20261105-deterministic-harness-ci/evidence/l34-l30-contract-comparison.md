# L34 / L30: сверка контрактов

Источники: `scripts/codex-unix-boundary.py`, `scripts/codex-unix-entrypoint-client.mjs`, `deploy/fleet/rollout-node.py` функции `validate_installed_ci_receipt_structure` и `verify_installed_ci_evidence`, `evidence/receipt-l27-held-active-synthetic-collector.json`. Статус: совместимого доверенного production gate пока нет.

- `PreparedPeer.collect` использует локальный `systemctl --user show` и `/proc`, затем повторяет readback PID/starttime/listener/entrypoint и ancestry после сценария. Это доказывает неизменность наблюдавшегося тестового процесса на границах прогона, но **не** независимую привязку к ожидаемому post-switch поколению rollout. Предлагаемый L30 `expected.generation` должен поступать от владеющей транзакции и быть зафиксирован до collector; подставить поля из самой квитанции нельзя.
- Частичный и полный digest принимает вызывающий; сравнитель читает файлы и отдельно выполняет Node resolution. Их доверенное происхождение из candidate CI, аутентификация и привязка к rollout не реализованы. Результат содержит `artifactEvidenceStatus=unverified-provenance`; файлы/отдельный `require.resolve` не аттестуют модули, уже загруженные PID, и не доказывают весь runtime resolution closure.
- Реальная квитанция является одним Codex срезом с `status=INCOMPLETE`, `allRequiredScenarios=false`, а не envelope L30 `status=PASS`, `artifactEvidenceStatus=verified`, `scenarios` для всего набора harness. Она содержит exact IDs, held-active, число страниц и поисковый boolean, но не выдаёт proposed `deliveries`, `searchResults` с `partial=false`, полный связанный cursor-chain `transcripts`. Нельзя искусственно вывести эти поля из счётчиков.
- Негативная совместимость проверена исполнением L30 validator на реальной квитанции held-active: `installed CI receipt: receipt incomplete`. Expected для этой негативной проверки взят из той же квитанции и не является доверенным независимым доказательством. Синтетический test verifier `tests/test_l30_receipt_verifier.py` проходит, но не проверяет происхождение его fixture.
- Не изменять preflight/rollback для принятия такого результата: контракт и происхождение expected должны быть реализованы и независимо проверены до открытия gate. Передача Laplace поставлена deferred, сессия не пробуждалась.
