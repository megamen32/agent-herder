# L30: проект контракта структурной проверки

Статус: проект для согласования с Rawls, не формат существующей полной квитанции и не release authorization. `validate_installed_ci_receipt_structure(receipt, expected)` в integration `deploy/fleet/rollout-node.py` не подключена к acceptance. Действующие preflight и `verify_installed_ci_evidence` безусловно отказывают.

Независимый от квитанции доверенный context `expected`: unit; полный непустой уникальный список `required_harnesses`, определённый проверенной политикой release; `artifact_sha256` и `full_artifact_sha256` из доверенного CI; `generation` с PID, starttime, port, абсолютным entrypoint и упорядоченной `unitProcessChain` от unit до listener. Его источник, authenticity и атомарная привязка к транзакции ещё не реализованы; передавать значения, извлечённые только из самой квитанции, недостаточно.

Предлагаемый envelope: unit, status PASS, allRequiredScenarios=true, artifactEvidenceStatus=verified, `scenarios` с точным набором ключей из expected. На каждый harness проверяются before/after generation и частичный SHA; fullArtifactComparison с совпадающими candidate/installed SHA, пустым differences и одинаковым resume entry; два уникальных session ID; два completed delivery, два точных поисковых результата с partial=false, два связанных транскрипта с полными непрерывными цепочками курсоров; обнаружение active для одного из этих ID во время удержания модели; локальный счётчик запросов и его сумма по путям. Отсутствие полей, несовпадения, лишний либо недостающий harness отклоняются. Точная форма показана тестовой synthetic fixture в `tests/test_l30_receipt_verifier.py`; она не является реальной квитанцией.

Структурный результат не аттестует происхождение, сетевую изоляцию, неизменность загруженных модулей, содержимое транскрипта или подлинность отдельных boolean/полей. Нужны независимые доверенные источник данных, генерация списка применимых harness и подтверждённая семантика полноты поиска/страниц. Существующий Rawls `PreparedPeer.collect` выдаёт одиночный Codex результат INCOMPLETE без proposed envelope и полного proof; до handoff, согласования и реального consumer proof нельзя открыть preflight или использовать этот verifier для принятия.
