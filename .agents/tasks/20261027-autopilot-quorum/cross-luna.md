# Cross-challenge Luna

## Общая гипотеза, которую challenge ставит под сомнение

`Ledger + verifier` не превращает полноту в гарантию: это два модельных решения, способных согласованно ошибиться. Например, цель «провести импорт, проверить все строки и сообщить расхождения» при позднем «сделай быстрее, пропусти уже обработанное» может быть сведена к «ускорить импорт», а исходное обязательство сверки исчезнет. Сценарий замены тоже опасен: пользователь пишет «теперь только проверь отчёт», имея в виду текущий следующий шаг; экстрактор может отменить весь импорт. Цитата защищает от выдуманного удаления, но не от неверного толкования цитаты и области действия.

Не хранить один авторитетный смысловой ledger, которому модель может молча переписывать требования. События пользователя — неизменный источник истины; ledger — версионируемая, оспоримая проекция со ссылками на spans/сообщения и явными операциями add/clarify/replace/cancel. Код требует, чтобы replace/cancel указывали затронутые obligation IDs и цитату. Если однозначное сопоставление старых/новых требований не доказуемо, сохранять прежние обязательства, помечать конфликт и спрашивать пользователя; не продолжать суженную целью работу как будто она принята.

## Native Goals — активный второй controller

Если native Goal сам инициирует continuation и оценивает stop/completion, Herder-проекция не «транспорт»: обе стороны могут продолжить один turn или разойтись после уточнения. Нужен явный controller lease по `session_id + revision`: ровно один владелец запуска. При выборе native владельцем Herder может только зеркалировать события и применять permission/HumanStop/no-replay gate, но не посылать continuation; native verdict также не закрывает внешний goal без полного coverage receipt. Если native API не позволяет перехватить/обезвредить его собственный continue/eval, этот путь нельзя безопасно включать одновременно — выбрать один supervisor на сессию или исключить этот harness из MVP. Не обещать, что adapter решит split authority.

## Stale memo, permission и ложное завершение

Пример: до checkpoint permission разрешала отправку; затем пользователь отозвал разрешение, но cache-key учитывает только goal revision либо memo повторно использует старый receipt. Resume отправляет действие или verifier принимает старое доказательство. Поэтому изменения policy, HumanStop, pending input, account/resource identity и receipt state обязаны менять epoch/invalidating key; перед любым consequential tool и `done` нужны live code guard и актуальный readback. Кешировать только неизменный prompt prefix; permissions и evidence — свежие данные, никогда не принимать их из memo.

Даже сильный Codex verifier тем же семейством, которое извлекло ledger, может повторить ту же ошибку: оба считают «проверить отчёт» выполненным по созданному отчёту, хотя пользователь просил сверку строк. Final completion — conjunction структурного coverage и первичных receipts; verifier должен пройти исходные user events и сравнить coverage, а не только ledger. При недоказуемом покрытии статус incomplete. Иначе утверждение «нет ложного done» не подкреплено.

## Минимальный falsifier без запусков

Настольная трасса, без LLM/tool исполнения: показать последовательность исходной цели, двусмысленного позднего сообщения, отзыва permission, старого memo и native queued continuation. Проверить по state-machine контракту, что obligation не удаляется, revision/epoch инвалидирует memo, только один controller имеет lease, stale permission блокирует отправку, а `done` невозможен без receipt каждого исходного требования. Если контракт не позволяет выразить любой инвариант или допускает две команды continue — текущий MVP-проект не принят. Это не доказывает модельную точность; её необходимо будет проверить на размеченных реальных трассах до расширения rollout.

## Решение

Оставляю выбор эволюции Herder, но сужаю утверждение: ledger/verifier — нужные компоненты, не гарантия полноты. Требуются immutable event log, операционный revisioned projection, freshness epochs и single-controller lease до первого вертикального среза. Отказываюсь от native Goals как «пассивного транспорта» без доказанного выключения его controller; один владелец continuation на сессию обязателен. Слабое и пока нерешённое место — согласованная семантическая ошибка extraction и verifier. Нужна будущая слепая проверка полноты на длинных изменяемых целях; кэш и стоимость через Codex subscription неизвестны, API скидку не предполагаю.
