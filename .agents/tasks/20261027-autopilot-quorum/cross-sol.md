# Cross-challenge Sol → Luna и общих предположений

Вердикт: REVISE. Сходный выбор не подтверждает архитектуру. Наши предложения недостаточно строго отделяют полноту пользовательского поручения от полноты уже извлечённого ledger.

## 1. Полностью покрытый неполный ledger

Пользователь: «Исправь поиск, сохрани экспорт и выложи; проверку проведи через мой обычный MCP». Extractor оставляет поиск, экспорт, deployment, но теряет потребительский путь. Verifier безупречно закрывает три строки и ложно завершает задачу. Во втором случае «кабинет пока не трогай» ошибочно снимает всё обязательство отдельного кабинета вместо временного запрета редактирования.

Изменение: нужна двунаправленная сверка: каждый действующий фрагмент исходных запросов/поправок связан с обязательством или явным объяснением «не требование»; каждое обязательство связано с источником. Перед финальным done verifier читает сами пользовательские сообщения и существенные изменения, не только ledger. Никакой гарантии полноты из JSON coverage не следует. Для длинной истории сохранять индекс первичных пользовательских событий, не отдавать полноту на усмотрение tail packing.

Минимальный falsifier: вручную предъявить такой пакет и ledger с намеренным пропуском. Если спецификация допускает done без обращения к отсутствующему фрагменту, архитектура уже опровергнута; запуск не требуется.

## 2. Native Goals — самостоятельный controller

Native Goal видит idle и запускает continuation, пока Herder оценивает тот же snapshot. Herder отправляет следующий шаг либо считает цель paused; native продолжает. Даже один отправитель внешних промптов не устраняет внутреннего второго контроллера.

Изменение: отказаться от выражения «Native Goals как транспорт». Для каждого session выбирать режим владения lifecycle. В Herder-owned режиме native goal не активен. В native-owned режиме Herder не посылает continuation; opt-out/HumanStop/budget должны реально останавливать native controller, а не только обновлять Herder record. Если документированный API не даёт revision fencing и stop/readback, native интеграцию исключить из первого среза. Не симулировать её polling и запоздалой компенсацией.

Falsifier: диаграмма idle → HumanStop → native continuation. Любая допустимая отправка после принятого Stop без нового разрешения опровергает режим. На данный момент stop contract не доказан общим пакетом.

## 3. Кеш закрепляет старое разрешение

В prefix или memo осталось «можно публиковать», пользователь позже пишет «публикацию отложи». Даже актуальная goal revision не гарантирует актуальность evidence: другой deploy уже заменил runtime без изменения пользовательской цели.

Изменение: неизменный prefix содержит общие инструкции, не действующие разрешения. Текущие permissions/Stop/native snapshot проверяются кодом перед consequential action. Memo привязан также к policy и наблюдаемой версии ресурса; receipt остаётся историческим фактом, а утверждение «сейчас работает» требует подходящего свежего readback. Не обещать API cache breakpoints или скидки через Codex подписку: поддержка и фактическая экономия неизвестны.

## 4. Одинаковая ошибка planner и verifier

Оба считают HTTP 200 доказательством работающего UI. Разные prompts той же модели повторяют одну ошибку. Даже другая модель не заменяет недостающее наблюдение.

Изменение: consumer acceptance формулировать из пользовательского требования; evidence включает наблюдаемое действие и результат, точную версию/адрес. Нет такого доказательства — нет done. Существенные финальные решения проверять свежим контекстом с первичными требованиями и артефактами, без авторского убеждающего заключения.

Выбор сохраняю: минимальная эволюция Herder. Существенное несогласие с Luna и собственным первым текстом: native goal не следует включать даже условным «транспортом» в первый срез; структурная полнота ledger не является полнотой цели. Стоимость дополнительной финальной сверки unknown; экономить её удалением исходного поручения недопустимо.
