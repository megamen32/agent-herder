# Независимая проверка синтеза

## Конечный вердикт после проверки delta

**PASS для архитектурного решения.** Новый раздел decision.md «Обязательный контракт применения решения после независимой проверки» закрывает обе обязательные правки: атомарный commit учитывает durable пользовательский cursor, stop/control epoch и рестарт; cached done подчиняется этому барьеру и актуальности доказательств, полномочий и первичных материалов. Дополнительных обязательных архитектурных правок по этому delta нет. Первоначальный REVISE ниже сохранён как история.

PASS относится к контракту решения. Не проверены механизм сериализации, фактическое exclusive ownership, Codex adapter/auth, полнота extraction/audit и эффект на стоимость/качество. Минимальная будущая проверка — описанные в новом разделе гонки audit с уточнением/stop/рестартом и инвалидация memo при изменении внешнего результата/полномочий/доступности вложения, затем независимая оценка полного пользовательского результата. Tests/runtime не запускались; измеренное улучшение не заявляется.

## Что выдержало проверку

Выбор существующего Herder с одной opt-in целью согласуется с поручением. Исходные события, ревизии, производный ledger и сверка с первичными требованиями уменьшают риск подмены полной цели кратким KPI. Полезно явно различены исполнитель и контрольная модель, продолжение и prediction, ожидание и успех, модельная оценка и реальные доказательства.

Исключение native Goals controller из первого среза разумно: он самостоятельно продолжает работу. Добавление второго активного controller не нужно для проверки выбранной гипотезы и создаёт спор о владельце продолжения. Отложенная эксклюзивная передача управления — адекватная граница, без необходимости проектировать этот режим сейчас.

Экономия корректно сформулирована как гипотеза для измерения. Native subscription cache, API скидки и дешевизна сильной контрольной модели не объявлены доказанными. Текущий GLM default из report.md не выдаётся за уже внедрённый Codex control path.

## Обязательные правки

1. **Завершение должно иметь атомарный барьер входящих событий.** Фразы «новое сообщение инвалидирует» недостаточно: реплика может быть уже durable, но ещё не разобрана в новую goal revision, пока аудит применяет done. Зафиксировать один controller commit contract: audit привязан к native identity, goal revision, cursor всех принятых пользовательских событий, evidence version и stop/control epoch; переход в completed допустим только при атомарном совпадении этих значений и отсутствии необработанного пользовательского ввода. Несовпадение отменяет применение результата; stop/отключение режима отменяет также подготовленную отправку. Выбор goal revision сам по себе не является барьером. Такая же проверка нужна после рестарта, чтобы старый аудит не завершил новую работу.

   Минимальная будущая проверка: задержать audit и принять уточнение непосредственно перед commit; повторить с отключением режима и рестартом. Старый результат не закрывает задачу, новая реплика сохраняется и обрабатывается один раз.

2. **Семантический memo не должен превращать устаревшее доказательство в разрешение завершить цель.** Сейчас свежие разрешения/внешние факты обещаны «перед действием», но применение cached done может трактоваться как отсутствие действия. Указать, что completion commit также является защищённым переходом. Доказательства должны иметь происхождение, наблюдаемую версию/срок актуальности и требование, которое они подтверждают. Истечение/изменение доказательства, полномочий либо недоступность существенного первичного материала инвалидирует применимость memo, даже если transcript не изменился. UNKNOWN внешнего эффекта не означает ни повторную отправку, ни success. Полные первичные материалы должны действительно входить в coverage audit либо быть прочитаны им; наличие ссылки без доступа и молчаливое усечение запрещают done.

   Минимальная будущая проверка: неизменный чат, но отозванное разрешение, изменённый внешний результат или недоступное вложение. Старый memo не разрешает отправку или завершение; незакрытое требование остаётся видимым.

## Непроверенные предположения

Существующий adapter действительно сможет вызвать выбранную Codex control model через разрешённую подписку; exclusive controller ownership переживёт рестарт; raw-event provenance отличит поручение владельца от цитаты/агентского сообщения; extraction и audit обнаружат потерянное требование. Ни одно из этого здесь не проверялось. Модельные defaults и отсутствие скрытого fallback нужно назвать при реализации, а не выводить из доступности модели в каталоге. Для архитектурного PASS достаточно внести два контракта выше; утверждать качество, стоимость и доставку можно только после ограниченного реального среза и независимой оценки результата.
