## Почему self-wake пришёл в другой чат

Вызов из `ses_e91d881bdffe9EzDeWoWOQuIOP` явно передал
`owner.sessionId=ses_e8b048a8effeubo6KB4IsRTPs3`. Поэтому принятый
`wait_44c84d5ec74a4cd21dc12772aef2fdef` возобновил указанный чужой чат.
Этот таймер не повторяли. Через существующий `session_identity(announce=true)`
в исходную сессию опубликован её правильный ID, без запуска нового хода.

## Исправление MCP: установлено и проверено

`resume_after` без `owner` и `session_identity()` без `sessionId` используют
native metadata конкретного MCP-запроса. Новый инструмент или плагин не нужен.

| Клиент | Источник native ID |
| --- | --- |
| OpenCode | `_meta["ai.opencode/sessionID"]` |

| ZCode | `_meta["com.zcode/request-context"].session_id` |
