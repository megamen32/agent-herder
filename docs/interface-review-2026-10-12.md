# Интерфейс чатов и автоматизации — 12 октября 2026

По замечанию владельца переработаны боковая панель и настройки автоматизации.
Чаты занимают одну строку; полные названия, среда, машина и состояние доступны
в подсказке. Информация о подключении машин раскрывается отдельно. Окно настроек
центрировано, заголовок и закрытие остаются вне прокручиваемой области.

Автопилот и автопродолжение остаются отдельными страницами. В автопродолжении
есть вкладки «Восстановление» и «Автокомпакт». Переключение вкладок не размонтирует
формы и не сбрасывает несохранённые значения. У каждой формы своя кнопка сохранения.
Основные пороги сжатия — 35% контекста и пять сообщений человека; нужны оба условия.
Время, лимиты и правила отбора раскрываются отдельно.

Два независимых AI-участника использовали только headed Agent Browser, без
исходников, API и журналов. После свободного исследования они отдельно объяснили
назначение кнопок и порогов. Первый проход: оформление и понятность 8/10 на
1024×768 и 390×844. Каждое замечание исправлялось отдельно. Повторный проход
подтвердил отсутствие боковой прокрутки на телефоне, доступность сохранения и
закрытия, отсутствие перекрытия поля «Сжатий за час», понятность вкладок.
Участники не меняли настройки и не отправляли сообщения; свои браузеры закрыли.

Root отдельно сохранил пороги через интерфейс и проверил нативную сессию:
выбор GLM-5.3 без суффикса сохранил допустимый уровень мышления, затем восстановлен
GLM-5.3-Flash/high. Использован штатный `model-selection.getView` установленного
ZCode; workspace-config может быть пустым без выбранной задачи. Явно указанные
уровни не заменяются. Провайдер не меняется автоматически.
Изображение из нативной истории загрузилось через ограниченное session-images
хранилище. Прямой путь на файловой системе не принимается от браузера.

Проверка очереди: сообщение UI-GUIDE-842 сначала ожидало окончания ответа,
«Отправить сейчас» перевело его в guide, агент ответил GUIDE-842 в исходном ходе.
Нативный sourceCommandId совпадает; повторной отправки не было. Этот прогон выявил
зависание плашки подтверждения при несовместимой схеме событий. Исправление читает
точное подтверждение из нативных сообщений, даже когда журнал событий недоступен;
при ошибке схемы messages использует native snapshot. Неопределённость без
положительного подтверждения не разрешает повторную отправку.

## Проверки и доказательства

- Fast unit и focused integration: адаптер ZCode, свежий выбор модели, доставка
  сообщений, управление UI, отдельные настройки сред. Обычная сборка ограничена
  180 секундами с одним test worker; последние 114 проверок и оба compiler
  завершились за 27 секунд. Для исправления подтверждения добавлены два focused
  regression, ожидаемо 1 секунда, максимум 5 секунд: сначала RED, затем GREEN.
- Browser consumer: 1024×768 и 390×844; ожидаемо 120 секунд на участника,
  максимум 180 секунд на заключительную проверку. Цель — обнаружить обрезание,
  перекрытие управления и непонятное действие, а не проверить CSS-строки.
- Итоговые runtime/source, native guide и таймер сжатия фиксируются в
  `trash/logs/interface-delivery-final-20261012/acceptance.json` после живого
  readback. Один unit GREEN не означает успех этой проверки.

## Границы исходной большой задачи

Оформление и проверки выше не означают завершение всех чужих чатов за 48 часов.
Ночная политика автопилота остаётся ZCode-only; Codex используется для
восстановления после сбоя. Остановки человеком и индивидуальные исключения
сохраняются. Пятиминутный TTL Z.AI не опубликован: 300 секунд — оценка пользователя.

Переданный владельцем incident-human-loop результат требует отдельного review
пары Herder `f356104` / Notice `2c54bd8` и живой проверки исходной карточки.
Это source-only передача, её нельзя считать живым восстановлением и нельзя
повторять неизвестные ранее принятые сообщения.
