# Браузерное расширение Agent Herder

## Что система делает сейчас

В checkout есть собственное расширение Chrome и прямой WebSocket-канал до Rust. В изолированном CI этот транспорт используется для ChatGPT/Z.ai send и сценариев ChatGPT recovery; fake fixture также считает submit, user ID и readback. Это подтверждает кодовый extension path, но не установку или авторизацию в обычном профиле server100. [Сборка](../../integrations/chrome/agent-herder/build.mjs) · [Подключение](../../integrations/chrome/agent-herder/background.js) · [Rust listener](../../crates/herder/src/adapters/browser/extension.rs) · [Workflow](../../.github/workflows/fleet-session.yml)

## Проблема

Пакет, загруженный в тестовый профиль Chrome, не появляется в обычном профиле пользователя. Подключение, аккаунт и страница могут измениться независимо. Попытка решить это посредником добавляет ещё одну точку отказа и скрывает, к какому браузеру подключён Herder.

## Идеальная система

Расширение напрямую общается с Herder и выполняет команды сайта в авторизованном профиле Chrome. Установка видна в `chrome://extensions`. Текущий Rust listener принимает loopback WebSocket `/browser-extension`; удалённый WSS использует reverse proxy с сохранением upgrade и пути. bezbrowser — отдельная совместимая браузерная система, не транспорт этого Rust расширения. UserIO относится к профилям совместимости.

## Идеальный конечный результат

Пользователь видит установленное расширение в своём Chrome; оно подключается к нужному owner после перезапуска браузера и работает на существующем аккаунте. При потере соединения Rust показывает, дошла ли команда до расширения, а после подключения сверяет исходное действие. Отправленный ввод появляется один раз.

## Анализ по ТРИЗ

Цепочка: дополнительный браузерный посредник → дополнительное подключение и привязка вкладки → больше случаев, когда авторизованный профиль есть, а команда до него не доходит. Техническое противоречие между лёгкой установкой и точным выбором аккаунта разрешается разделением по уровням: доверие к подключению подтверждается при установлении канала, контекст вкладки сверяет расширение перед фактическим действием. Функцию посреднического управления страницей уже умеет выполнять расширение. [Раздельные аккаунты](browser-accounts.md)

## Ресурсы

Имеются профиль Chrome, site authorization, собственный extension, приватный token file, loopback listener и защищённая authority. Команды локальной сборки и поля описаны в [browser-chat-adapters](../browser-chat-adapters.md#local-extension-package-and-owner-profile).

## Спецификация

- Rust выбирает экземпляр и операцию. Прямой транспорт доставляет команду в его профиль. При подключении проверяется токен. Для чтения и отправки в существующий чат граница эффекта проверяет account scope и chat ID. Дополнительные `failed turn` и `input ID` нужны только для recovery. [Операции веб-чата](browser-chat-adapters.md)
- Расширение подключается к listener. На той же машине используется `ws://127.0.0.1:<port>/browser-extension`; для удалённого WSS reverse proxy сохраняет upgrade и путь. Токен хранится в защищённом профиле и в options расширения.
- Отказ до начала действия даёт однозначный результат. При потере ACK после начала — readback исходного ключа и сверка нативной квитанции. Неподтверждённый исход влияет только на повтор этой отправки; чтение и наблюдение продолжаются.

## План и приёмка

1. Собрать версионированный каталог через [build.mjs](../../integrations/chrome/agent-herder/build.mjs). В обычном профиле Chrome на 100 открыть `chrome://extensions`, загрузить именно этот каталог и сверить имя и версию расширения. Настроить provider, endpoint и token для него по текущей [инструкции владельца](../browser-chat-adapters.md#local-extension-package-and-owner-profile). Использовать `AHAP_BROWSER_TRANSPORT=herder-extension`. Логин на другой машине не нужен, когда на 100 уже есть нужный авторизованный профиль. Одобрение CDP не входит в установку.
2. Быстрая проверка первой отправки — [browser_adapter_smoke.py](../../tests/native/browser_adapter_smoke.py) с `--bin-dir <каталог> --extension --harness chatgpt --surface mcp --content text --iterations 1`. Для recovery использовать тот же fixture с `--extension --recovery success`, затем адресный negative case, соответствующий меняемому поведению.
3. Минимальная квитанция установки содержит версию пакета и owner, account scope, результат чтения точного чата и квитанцию одной отправки в выделенный тестовый чат. Проверить переподключение после рестарта, используя тот же профиль.
