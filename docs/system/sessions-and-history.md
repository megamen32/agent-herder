# Сессии, история, поиск и экспорт

## Что система делает сейчас

Rust хранит привязки `node / instance / native session` и строит список сессий из снимков источников. Результат перечисляет доступность и полноту каждого источника. `session.recent` выдаёт пару последних реплик, `session.messages` читает страницы нативных сообщений, `search` применяет ACL до подсчёта и выдачи. Обычный transcript export сохраняет нативное происхождение. В Web уже есть Codex-пагинация от конца rollout через WASM-читалку и кнопку старших страниц. ## Проблема

Для первого экрана важна свежая часть истории. Чтение с начала большого лога замедляет открытие и может показать давно неактуальный ход. Поиск, recovery и экран чата имеют разные задачи и сейчас используют разные единицы страницы: сессии, turns, нативные items, сообщения и сырые события. Общий числовой предел не гарантирует актуальность или полноту.

## Идеальная система

При открытии сразу видны последние 100 отображаемых сообщений, либо вся короткая история. Предыдущие сообщения подгружаются при переходе вверх. Решение о состоянии чата запрашивает последний релевантный ход напрямую. Поиск и полный экспорт работают отдельно и возвращают происхождение результата и доступный охват.

## Идеальный конечный результат

Чат с большой историей открывается на актуальном контексте за ограниченную работу. При догрузке страницы и поступлении нового сообщения позиция и порядок сохраняются, дублей нет. Результат поиска открывает точный нативный ход. Отключённый источник заметен в покрытии и не исчезает как якобы пустой.

## Анализ по ТРИЗ

Техническое противоречие между моментальным показом и полнотой больших журналов. Цепочка «прочитать всё перед показом → задержать актуальный кусок → ввести общий предел → отсечь нужный хвост» разрывается разделением во времени и по назначению. Экран читает tail и догружает, индекс обновляется отдельно по изменениям, экспорт читает полноту по отдельному запросу, а recovery читает точный последний нативный ход. Каждая функция использует уже имеющийся подходящий источник.

## Спецификация

1. Владелец держит адрес и доступ. Нативный источник владеет содержимым и порядком. Чистая функция нормализует page, применяет окно и объединяет страницы по ID; транспорт читает индекс или каждую native page. При открытии экран начинает с конца и запрашивает до 100 отображаемых сообщений. Виды нативных событий получают явное описание, если предоставляют иной счётчик.
2. Курсор связан с нативным адресом и конкретной границей страницы. При append запрошенная старая страница детерминирована. Подмена или ротация источника возвращает причину, по которой окно надо перечитать. Схема UI позволяет загрузить предыдущую страницу без сдвига видимого сообщения.
3. Поиск индексирует ограниченными порциями и сообщает timestamp, source и coverage. Права применяются до выдачи хитов и чувствительных счётчиков. Экспорт возвращает нативный transcript с provenance и доступной полнотой. Общий нормализованный экспорт остаётся отдельной неподтверждённой возможностью. [Контракт Rust](../AGENT-HERDER-SPEC.md)
