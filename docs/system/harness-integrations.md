# Интеграции, плагины и хуки харнессов

## Что система делает сейчас

Плагины регистрируют MCP и принимают нативные события сессий, команд, инструментов и завершения хода. Отдельные интеграции работают через скрипты OpenCode, ZCode, Hermes и Fast Agent. Хуки могут передавать наблюдения и контекст, а некоторые обладают правом отказа. У Codex есть отдельная сборочная проекция native hook package. Есть также совместимые способы привязать кнопку или callback к точной сессии. [Каталог хуков](../../src/hooks/catalog.ts) · [Интеграции](../../integrations) · [Пакет Codex](../codex-native-projection.md) · [ChatGPT wake](../chatgpt-wake-binding.md) · [UserIO Dots](../userio-dots.md)

## Проблема

Установленный пакет и доступный MCP сами по себе ничего не говорят о том, загрузил ли харнесс Stop-hook. Разные события одного хода могут повториться. Задержка фонового сборщика контекста способна заблокировать команду, если данные ошибочно проходят через ветку запрета.

## Идеальная система

Каждая интеграция переводит событие харнесса в единый факт для нужной системы. Базовые наблюдения работают быстро и независимо от доменных решений. Состояние исполнения хука и его право отказа учитываются отдельно. Плагин предоставляет контекст в пределах сессии.

## Идеальный конечный результат

После установки реальный харнесс показывает зарегистрированные хуки. Один нативный ход даёт каждому потребителю один полезный факт. Сессия работает при выключенной необязательной инъекции или потере связи с observer. Ответ на явный callback виден в исходном нативном чате.

## Анализ по ТРИЗ

Техническое противоречие между полнотой lifecycle-контекста и задержкой команд харнесса. Цепочка «синхронная инъекция → медленный внешний запрос → задержка и ошибочный отказ» разрывается разделением по условию. Установленное правило отказа проверяется быстро на границе действия. Наблюдение и справочный контекст обрабатываются отдельно. Копии автопилота внутри hook-скриптов избыточны, потому что решение принимает общий владелец правила.

## Ресурсы

Нативный ID события, каталоги и guard сроков хуков, раздельное состояние runtime и prohibitions, адрес сессии, существующая MCP-проекция, привязки Intro и wake. ## Спецификация

1. Чистая функция переводит тип и поля нативного сообщения в факт, разрешение или краткий контекст. Порты обеспечивают чтение конфигурации, запись факта и вызов API. Дедуп по `harness / session / turn / event` применяется там, где факт вызывает эффект.
2. Для нативного контекста нужны точный session ref и разрешённый scope. Включение хуков, разрешение на запрет и HumanStop отображаются независимо. Вызов ограничен по времени, результат содержит тип и подтверждение регистрации или исполнения.
3. Кнопка или callback несёт привязку к существующей сессии, использует действие своего owner и читает его квитанцию. Прямой транспорт расширения обслуживается своим контрактом. [Веб-расширение](browser-extension.md) · [Автопилот](autopilot.md)

Отдельно проверить действия с отключёнными prohibitions и повтор одного события.
