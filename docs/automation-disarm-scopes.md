# Рычаг «автоматика запрещена»: области вместо одного выключателя

Рычаг запрещает **автоматические** запуски в указанной владельцем области
проекта. Это не кнопка «остановить всё»: ручной путь (запуск, начатый
человеком) продолжает работать, а запрет живёт только в точке допуска к
запуску сессии.

Состояние — durable-файл рядом с живой launch-policy:

```
~/.local/state/agent-herder/autopilot-live/automation-disarm.json
```

Файл читается при каждом решении о допуске, поэтому запрет переживает
рестарт рантайма и не зависит от памяти процесса.

## Форма записи

Одна запись — одна область:

```json
{
  "scope": "/home/roomhacker/agents-projects/agent-herder",
  "forbidden": true,
  "owner": "owner-1",
  "reason": "владелец остановил автоматику в этом проекте",
  "createdAt": "2026-10-22T08:12:03.114Z",
  "policyRevision": "\"5f1c…\"",
  "workKeys": ["opencode\u0000/home/roomhacker/agents-projects/agent-herder\u0000card-42"]
}
```

| Поле | Смысл |
| --- | --- |
| `scope` | `"*"` — вся автоматика; иначе абсолютный путь проекта (канонический, realpath). |
| `forbidden` | `true` — запретить, `false` — явно разрешить. |
| `owner` | Идентификатор владельца, принявшего решение. |
| `reason` | Свободный текст владельца. |
| `createdAt` | Когда записано решение. |
| `policyRevision` | Ревизия живой launch-policy на момент записи (etag из `GET /api/automation/launch-policy`) — след для аудита. |
| `workKeys` | Необязательная более тонкая граница внутри области: канонические ключи `harness\0каталог\0имя` (NUL-разделители сохраняются). |

Файл целиком:

```json
{
  "version": 2,
  "records": [ { "scope": "...", "forbidden": true } ],
  "changedAt": "2026-10-22T08:12:03.114Z",
  "changedBy": "owner",
  "disarmed": false,
  "blockedWorkKeys": []
}
```

`records` — authority. `disarmed` и `blockedWorkKeys` — плоские зеркала для
раньше формата: узел, который знает только его, всё равно прочитает рычаг, а
не примет его за поднятый.

Записи упорядочены по `scope`.

## Семантика области

Область запрета ищется **по проекту и каталогу**, а не по id сессии:

| Запись | Что запрещает |
| --- | --- |
| `scope: "*"` | любой автоматический запуск, где угодно |
| `scope: "/proj"` без `workKeys` | любой автоматический запуск в `/proj` и **внутри** него |
| `scope: "/proj"` с `workKeys` | только перечисленные работы внутри `/proj` |
| `scope: "*"` с `workKeys` | только перечисленные работы, где угодно |

Правило выбора: побеждает **самая узкая** подходящая запись. Запись
`scope: "/proj", forbidden: false` снимает запрет внутри `/proj`, но не
трогает запрет `scope: "*"` для остальных проектов. Явное разрешение той же
области побеждает более ранний запрет этой области: запись на область одна,
upsert её заменяет.

Сопоставление каталогов каноническое: и область, и каталог запроса приводятся
к realpath, поэтому симлинк и его цель — одна область. Каталог запроса лежит
внутри области, если он равен ей или начинается с неё.

Ключ работы — тот же, что и у сессии: `harness\0realpath(cwd)\0имя`. Вторая
схема ключей не вводится. Для диспетчеризации проекта ключ проекта содержит
путь проекта, поэтому проект сопоставляется по тому же пути.

## Ручка чтения

```
GET /api/automation/disarm
Authorization: Bearer $AGENT_HERDER_DISARM_TOKEN
```

Ответ `200`:

```json
{
  "ok": true,
  "records": [ { "scope": "/proj", "forbidden": true, "createdAt": "…" } ],
  "state": { "records": [], "changedAt": "…", "changedBy": "owner" },
  "nodes": [ { "hostId": "roomhacker-server-100", "status": "confirmed", "reason": null } ],
  "summary": "the owner state holds 1 records, 1 forbidden; state confirmed on 5 nodes",
  "etag": "\"9a1f…\""
}
```

Заголовок `ETag` несёт ревизию состояния; тело повторяет её в `etag`.

Чтение **требует того же секрета**, что и запись: рантайм доступен на
`0.0.0.0:18791`, а состояние показывает области проектов — это не то, что
должно быть видно без авторизации.

Коды ответа: `200` — состояние прочитано, `401` — нет/неверный секрет,
`503` — секрет на узле не настроен (fail closed).

## Ручка записи

```
POST /api/automation/disarm
Authorization: Bearer $AGENT_HERDER_DISARM_TOKEN
Content-Type: application/json

{ "source": "owner", "scope": "/home/roomhacker/agents-projects/agent-herder",
  "forbidden": true, "owner": "owner-1", "reason": "стоп" }
```

Семантика — **upsert** записи для `scope` с указанным `forbidden`.

| Условие | Ответ |
| --- | --- |
| `source` не `"owner"` | `403`, ничего не меняется |
| нет/неверный `Authorization` | `401`, ничего не меняется |
| секрет на узле не настроен | `503`, fail closed |
| `scope` не `"*"` и не абсолютный путь | `400` |
| `forbidden` не boolean | `400` |
| `If-Match` не совпал с текущим ETag | `412`, ничего не меняется |
| успех | `200` + заголовок `ETag` |

Тело успешного ответа:

```json
{
  "ok": true,
  "applied": true,
  "scope": "/proj",
  "forbidden": true,
  "disarmed": false,
  "state": { "records": [], "changedAt": "…", "changedBy": "owner" },
  "records": [],
  "nodes": [ { "hostId": "roomhacker-server-100", "status": "confirmed", "reason": null } ],
  "summary": "new launches forbidden (saved); scope /proj; admission forbidden confirmed on 5 nodes",
  "etag": "\"9a1f…\""
}
```

`nodes[]` и `summary` присутствуют всегда: голого «success» без списка нод
нет. Статусы нод: `confirmed`, `declined`, `unreachable`, `no_runtime`. Фразы
сводки: `new launches forbidden (saved)` / `new launches allowed` /
`node X did not answer — its state is unknown` /
`node X declined — its state differs` /
`admission forbidden confirmed on N nodes`.

`If-Match` — необязателен: без него запись разрешена (write-по-умолчанию),
ответ всё равно содержит новый ETag. С ним запись становится
compare-and-swap: состояние, прочитанное ранее, должно совпасть.

Снятие запрета — **тот же** интерфейс, не отдельный метод:

```
POST /api/automation/disarm
{ "source": "owner", "scope": "/proj", "forbidden": false }
```

Раньше формат (`version: 1`) читается и разворачивается в записи: плоский
выключатель становится записью `scope: "*"`, а `blockedWorkKeys` — записями по
области из ключа. Ничего не теряется молча.

## Код отказа

Отказ запуска в запрещённой области возвращает **стабильный машиночитаемый
код**:

```
automation_disabled
```

Код едет в теле ответа MCP/HTTP-запуска (`failureCode`), человеческий текст —
отдельным полем (`error`). Код отличается от `HUMAN_STOP_MESSAGE`: тот
означает «этот чат остановлен человеком», новый — «автоматика запрещена
владельцем в этой области».

Литерал один на весь контур: `automation_disabled` — тот же класс отказа,
что уже называет health-контур в своём наборе кодов. Третьего написания
того же отказа не заводим.

## Область отказа

Область едет **отдельным структурированным полем** `routingReasonDetail`
рядом с кодом, а не внутри текста `error`:

- `*` — весь контур (catch-all область);
- канонический путь области проекта или каталога;
- для записи с конкретными work-ключами — канонический путь области, к которой
  относится запись.

Имя поля — то же, что и в health-контуре (пара `routingReasonCode` +
`routingReasonDetail`), поэтому носитель области один и тот же на обоих
путях. Текст `error` остаётся человеческим: читать область из него не
нужно.

Отказ по запрету **не является ошибкой доставки**: он помечается
`nonRetryable: true`, потому что повтор той же заявки будет отклонён так же.

## Что происходит при рестарте

Ничего особенного: файл состояния перечитывается при каждом решении о
допуске. Запрет, записанный до рестарта, действует сразу после него.
Автоматический путь (лаунчер незавершённых сессий, автопилот, resume после
рестарта) запрет **не снимает и не обходит**: он может только быть отклонён.
Снимает запрет только явное действие владельца — `POST` с `forbidden: false`
для той же области.

## Чего рычаг НЕ делает

Рычаг стоит **только** в пути допуска к запуску сессии. Он не блокирует:

- сбор событий (`herder-events`);
- создание инцидентов (`autopilot/notice-incident`);
- доставку уведомлений (`user-message-delivery`).

Эти механизмы живут на стороне mesh и центра, herder их не касается.

Ручной путь жив: запрос с `humanRequested: true` запускается, даже когда
автоматика в его области запрещена.
