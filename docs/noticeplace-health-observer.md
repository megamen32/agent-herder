# Наблюдатель исполнителя Notice Place

Центр Notice Place заводит health-инцидент, запускает исполнителя (AI-агента) в
herder и ждёт, пока карточка инцидента остаётся правдивой. Карточку закрывает не
наблюдатель, а независимая проверка источника (сторож OmniRoute шлёт
`/health/verification`). Наблюдатель только публикует прогресс.

## Что видно в карточке

В карточку инцидента попадает **структурная сводка**, а не сырой текст модели:

```
Исполнитель работает; по данным сессии; статус: running; сообщений в сессии: 12;
инструменты: bash, read; последнее сообщение: исполнитель. Фрагмент: «Продолжаю разбор…»
```

Правила сводки:

- источник всегда назван («по данным сессии»), поэтому неполная история
  (`history.source: acp-load`, `complete: false`) не читается как факт;
- приведён только **редактированный** фрагмент последнего сообщения: перед
  публикацией вычищаются `Bearer <значение>`, значения `api_key` / `token` /
  `secret` / `password`, длинные hex/base64-подобные строки (32+ символов) и
  секреты в query-строке;
- длина шага ограничена 220 символами.

Токен исполнителя (он читает защищённый callback-файл) в карточку попасть не
может: публикуется только сводка, а фрагмент проходит редактуру.

Финальные строки:

- `Исполнитель закончил работу (статус stopped); ждём независимую проверку источника.`
- `Наблюдение остановлено по лимиту времени; ждём независимую проверку источника.`
  (45 минут наблюдения — жёсткий предел, дальше наблюдение молча прекращается).

## Когда наблюдение заканчивается

| Признак | Итог |
| --- | --- |
| `status = stopped` / `error` | исполнитель закончил — публикуется финал |
| `status = idle`, есть активный native-turn | исполнитель **жив**, наблюдение продолжается |
| `status = idle`, нет активного turn и нет активности 3 минуты | исполнитель закончил — публикуется финал |
| `status = running` / `needs_input` | наблюдение продолжается |

`idle` в herder означает «ждёт, запроса нет», а не «конец»: собственный словарь
статусов (`src/types/common.ts`) прямо различает `idle` и `stopped`. У busy-сессии
статус тоже может прийти как `idle`, поэтому одного статуса недостаточно: нужен
ещё и активный turn, и тишина в 3 минуты.

## План инцидента

Центр принимает прогресс только для **выбранного** плана инцидента
(`observe` / `repair` / `verify`). Herder публикует прогресс ровно с тем планом,
который пришёл с запуском:

- план из тела запроса запуска (`plan_id` в `POST /api/health/remediation`);
- план, названный центром в сообщении запуска (`selected plan <plan_id>`);
- repair-first запуск (у инцидента ещё нет карточки плана) — план `repair`, так
  же, как публикует сам центр.

Неизвестный план **не подставляется**: наблюдение не стартует, в журнале появляется
явная запись. Молчаливый `repair` приводил к тому, что центр отклонял 100 %
прогресса по инцидентам с карточкой плана.

## Восстановление после перезапуска herder

Перезапуск herder не обрывает наблюдение: при старте сервера armed-сессии
читаются из `~/.local/state/agent-herder/autopilot-live/sessions.json` и
вооружаются снова — только те, что ещё живы. Кандидаты проверяются и
вооружаются небольшими партиями, чтобы рестарт не превратился в шторм
нативных чтений.

## Ограничения

- одновременно наблюдаются не более 8 исполнителей;
- одновременно выполняются не более 4 нативных чтений сессии; при переполнении
  тик пропускается, а не ставится в очередь;
- отказавшая публикация повторяется с тем же содержимым, но не чаще одного раза
  в 60 секунд на цель;
- чтение сессии наблюдателем проходит ту же проверку привязки проекта, что и
  обычные HTTP-маршруты.

## Авторизация починки

`POST /api/health/remediation` сегодня вызывается **без** bearer-токена, поэтому
требование авторизации выключено по умолчанию. Включается одним переменной:

```
NOTICEPLACE_HEALTH_REMEDIATION_REQUIRE_BEARER=1
```

После включения центр обязан слать `Authorization: Bearer <NOTICEPLACE_HEALTH_LAUNCH_TOKEN>`
(тот же токен, что и для анализа инцидента). Без этой переменной дыра
«локальный процесс запускает автономного агента» остаётся: слушатель — только
loopback (127.0.0.1:18787), но любой локальный процесс туда дотягивается.
