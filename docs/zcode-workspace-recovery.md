# ZCode hook lifecycle and workspace crash recovery

The existing native hooks are the primary source of begin, progress and explicit successful completion. `/api/coordination/lifecycle` resolves the exact native turn and promoted input intent from SQLite, including when UserPromptSubmit omits input_id. It persists begin in UnfinishedSessionStore before returning HTTP success. Automation never releases HumanStopStore; an actual Desktop input can release it only with its native identity and timestamp. Unknown actors are refused.

PreToolUse/PostToolUse report progress through the same endpoint. Stop reports continue, failed, needs-input, manual-stop, unknown or success. Success requires an explicit completed verdict, the exact final native assistant, settled tools, no Stop and a fresh read of pending human questions. A hook invocation, missing next goal, assistant finish or semantic autopilot disabled does not prove the task complete. Matching generic SDK model-turn completion retains hook-primary tracking and the durable active record until verified Stop success; technical waiters and accepted queue scheduling still receive the native receipt. Native cancellation continues through the existing human-stop evidence path. The runner retains its compatible terminal decision and exposes terminalKind to distinguish completed from needs-input and unknown. In particular an OFF semantic policy produces unknown, not success; no policy is enabled by these hooks.

The existing supervisor inventory tick provides the SIGKILL fallback, without another timer, registry or planner. The adapter observes only its own accepted inputs or backend-verified automation hooks. Before failure it reads the public getWorkspaceRuntimeIdentity and readSession with existing-only, then records the exact own SDK PID, workspace CLI PID/start tick/generation/cwd, native input/user/turn and sampled child identities. For the same CLI generation, descendant PID/start-tick observations accumulate across captures, including children that reparent or change process group; an empty later tree does not erase them. Loss is recognized only from ZCODE_AGENT_RUNTIME_UNAVAILABLE for that previously observed runtime. Timeouts and unknown observations are not losses. Any surviving process group or recorded child, newer Desktop input, successful native tail, pending admission, unknown native state or human Stop refuses recovery.

A confirmed workspace loss emits one session-scoped process.disconnected into the existing launcher. Existing autostart/recovery settings govern the same-SID resume and a new continuation command; semantic autopilot can remain OFF. The original input/command is never resent and executed tools are not replayed. After resume the ready-only snapshot and final synchronous native/process fence protect dispatch; no synthetic completedAt or generic cancelled reinterpretation is used. This fence is not a native idle CAS: public queue delivery avoids preempting a newly admitted turn, and unknown admission remains receipt-only.

## Verification and runtime boundary

Fast unit: tests/zcode-autopilot-hooks.test.ts, expected 5 seconds, maximum 15 seconds; actual hook subprocesses against an isolated HTTP receiver discriminate terminal outcomes and missing input_id attribution.

Focused integration: tests/zcode-workspace-lifecycle.test.ts, expected 20 seconds, maximum 40 seconds; isolated SQLite, injected ready SDK/process observations and actual local HTTP handler prove durable begin, same-ID automatic continuation, no original resend, surviving-child/timeout/Stop/Desktop refusal and pending-question success refusal. These fixtures invoke no production provider or model.

The configured native hook commands can point directly into the canonical checkout. Consequently source changes to hooks are hot for subsequent invocations, even before a backend build. The runtime owner must coordinate the reviewed hook/backend boundary and run the real isolated crash acceptance. Source checks alone are not that acceptance. The actual test uses one initial input, durable active identity before exact own CLI kill, then observation only; it must show new automatic activity in the same SID and completed steps [1,2,3], with step1 executed once. Terminal business success additionally requires the explicit completed outcome above. No original-business or foreign sessions are crash fixtures.

## Hard crash of the Herder parent

The observation tick automatically persists activeNativeOwner on the existing unfinished record while the exact promoted native turn is still active: controller generation/PID/start tick and documented own systemd INVOCATION_ID/unit, SDK PID/start tick/direct-parent identity, workspace CLI birth/cwd, input/user/turn and the accumulated child identities. The two production adapter construction paths share the launcher generation and the same existing store callback. Persistence uses its strict atomic writer and matches the live active identity before writing; no maintenance checkpoint or external crash packet is used. A metadata refresh cannot relabel the previous owner while this proof is active.

Startup reconciliation can qualify that previously recorded generation only when the old controller, SDK, workspace CLI and all observed descendants are gone, and the exact latest own promoted input/turn has a native cancelled terminal interval containing the prior live observation. Its cancellation must also occur at or after the authoritative old-invocation systemd SIGKILL exit, compared in microseconds. A bounded read-only journalctl --user-unit=agent-herder.service lookup requires that exact USER_INVOCATION_ID, process-exited MESSAGE_ID and killed/9 receipt; unavailable/ambiguous exit evidence or cancellation before death defers recovery. Missing proof, unknown native data, success, surviving actors, pending input/questions, Stop or a newer Desktop user refuse adoption. Generation/cancelled status alone do not authorize recovery. The existing store then marks process.disconnected and the existing attempt is claimed before supported same-SID resume/load/send. The original prompt is never replayed; accepted/unknown continuation admissions stay receipt-only. A late native cancellation receipt is suppressed only when its exact turn/input/timestamp matches this qualified dead-owner proof and the authoritative native cancelled row; unrelated cancellations keep the human-stop path. Fresh question/Stop and native/process fences remain at resume/send. Legacy records, including the first actual failed parent-crash fixture, acquire no retrospective proof.

Focused integration covers automatic pre-loss persistence, a new adapter/launcher generation with no disconnect/checkpoint event, original input count one, accumulated detached children and the refusal cases above. Only a new Root-owned real parent SIGKILL test after reviewed paired delivery can prove this hard-crash path in production. The earlier workspace-CLI SIGKILL acceptance is a separate boundary.
