# Driving Claude Code from Agent Herder

Use the TypeScript Agent SDK with one streaming query per owned session. It is already pinned in package-lock.json (0.3.207). The SDK handles framing, control replies and cancellation and can read the native session store after the process exits. Another agent can call Herder's MCP tools without having a Claude process or Claude credentials of its own.

| Transport | Active input and resume | Permissions and history | Version, authentication and cost to implement |
| --- | --- | --- | --- |
| Headless CLI | Keep stdin open with `claude -p --verbose --input-format stream-json --output-format stream-json`. A separate `--resume ID` starts a new process. `--session-id UUID` chooses a fresh identity. | CLI permission modes and MCP permission-prompt tool. JSONL under ~/.claude/projects/&lt;project&gt;/, also a sessions/ subdirectory in older installs. A controller would need control-frame handling, cancellation and process ownership. | Documented CLI flags, less protection from wire changes. Uses the host's Claude login or configured API provider. Medium effort. The permission-prompt-tool flag was absent from ordinary help on this host and was not exercised. |
| TypeScript / Python Agent SDK | Streaming user input on a retained query, explicit interrupt/close, resume by UUID in the original cwd. TypeScript 0.3.207 declares input priority now/next/later. No public attach to an arbitrary existing terminal's stdin. | canUseTool, abort signals and hooks. TS listSessions, getSessionInfo, getSessionMessages and native JSONL. | Official versioned client, bundled executable. Existing TS dependency and MCP adapter registry minimize integration work. Python adds another runtime. Host login is used by the Claude process. For distributed applications use Anthropic's supported API-key/provider auth and check current subscription terms. Python SDK behavior was not exercised on this host. |
| Remote Control / cloud | Remote Control attaches the Claude web/mobile UI to a local process. The documented cloud CLI creates cloud sessions with --cloud and queues follow-ups with -p --cloud SESSION_ID; --teleport can pull a cloud session into a local terminal. | Web/mobile handle prompts and conversation history. No verified public API to attach, steer and answer local-session permission callbacks through that UI. | Remote Control requires a supported subscription. API keys are unsupported there. Anthropic Managed Agents is a separate developer API with distinct session identities. Building against private claude.ai endpoints would be high maintenance. Cloud execution was not tested. |
| ACP / Zed Claude adapter | session/new, session/prompt, session/cancel. Negotiate loadSession and resume capabilities with the installed protocol version. Load replays history, resume can skip replay. Concurrent prompt steering is adapter/version dependent. | session/request_permission and streamed session/update. Loading historical sessions depends on the adapter. | Public versioned protocol, separate bridge and dependency on its Claude backend. Authentication is negotiated by the bridge (Claude login or provider configuration). Medium effort with Herder's existing ACP client. No claude-code-acp binary on this host. |

The installed standalone CLI reports 2.1.202. Its help confirms stream JSON, session ID, resume, effort, permission mode and Remote Control. The SDK declarations in the locked package establish the TypeScript surface. The existing CLI adapter launches a detached process per message, the SDK adapter on the base branch opens a fresh query per send, and the external Go session reader implements discovery and history only. The Rust native registry on the base branch has no Claude owner.

Sources: [headless CLI](https://code.claude.com/docs/en/headless), [SDK permissions](https://platform.claude.com/docs/en/agent-sdk/permissions), [Remote Control](https://code.claude.com/docs/en/remote-control), [ACP sessions](https://agentclientprotocol.com/protocol/session-setup), [Zed Claude adapter](https://github.com/zed-industries/claude-agent-acp).

## MCP usage

Use the SDK transport (the default when Claude is enabled). The cloud orchestrator needs access to the Herder MCP endpoint. The session runs in the target host's working directory under its configured Claude identity.

| Tool | Arguments or result |
| --- | --- |
| create_session | `{"variant":"native","harness":"claude","cwd":"/work/project","name":"review","model":"sonnet","effort":"medium","permissionMode":"plan","thinkingBudget":4096}`. The response waits for the native initialization, input echo and persisted title. Initialization does not ask the model to generate a response. Retry the same name in the same canonical directory after a gateway failure. |
| list_sessions | Use scope=history, harness=claude and a small limit. Listing uses the SDK index. A native custom title takes precedence over the first prompt. |
| deliver | Use the returned sessionId. Use activation=always for the first task. The default on an existing target steers an owned active turn. Each asynchronous delivery waits for its native user-message echo. |
| session_info | view=compact includes readiness, effective settings, turn status, last tool and last assistant line. Closed-session progress samples up to 64 KiB from the transcript tail. view=messages returns conversation items. export_transcript provides the native JSONL. |
| respond_permission | Read permissionDetails from session_info. Pass sessionId, harness=claude, permissionId and response=allow or deny. The SDK callback is session-scoped. Abort, stop or a five-minute timeout denies outstanding requests. |
| Stop and resume | Stop closes Herder's owned query. Resume reopens the persisted UUID in its native cwd with its saved launch settings. Steering and stopping an independently launched terminal require ownership of that terminal. |

The SDK runtime bundled here is Claude Code 2.1.207. Model and permission mode come from native events. The pinned runtime's optional get_settings control reports applied model and effort and the effective configured MAX_THINKING_TOKENS ceiling. Turn hooks can report model-specific effort downgrades. Adaptive-thinking models can decide their own actual token spend. Unavailable readback fields remain unknown. Claude has no Codex serviceTier field.

For a Rust scoped owner, configure a trusted profile with kind=claude, the absolute Node executable and ahap_script pointing to the built dist/ahap-claude-runner.js. The runner uses the profile's code_home and cwd. The TypeScript MCP supplies the named-create settings, compact session_info and respond_permission described above. The generic Rust scoped-create contract supplies its profile name and cwd. The Go reader remains suitable for inventory-only installations.

Run the offline MCP contract with `npx vitest run tests/claude-sdk-lifecycle.test.ts`. Set HERDER_CLAUDE_SMOKE=1 for local SDK persistence, stop and resume. Add HERDER_CLAUDE_MODEL_SMOKE=1 to require an actual model reply in the resumed session. The host's standalone CLI reported an OAuth login. An isolated model call returned authentication_failed; native persistence and control can work in this state. No credentials are required in test arguments or output.

The reproducible offline smoke runs the compiled AHAP runner, bundled Claude binary and a loopback Messages API. It checks native settings, the resumed UUID, a real Write permission callback and denial, assistant transcript, terminal digest and reconciliation using the original delivery key. Run `npm run build:core && npx tsc && python3 tests/native/claude_sdk_smoke.py`.
